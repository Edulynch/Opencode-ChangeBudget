## Implementation boundaries

- Keep provider-neutral policy in `src/core/authority/authority-service.ts`; add no package-root/public SDK export, dependency, service, database, cloud registry, migration, or provider-specific authority semantics.
- Keep the core compact under `src/core/authority/` for physical repository identity, work/subject binding, registry, grants, and deterministic verification. CLI integration belongs in the established `src/cli/commands/authority.ts` route with dispatch/help changes only in `src/cli/index.ts` and `src/cli/help.ts`; no public SDK export.
- Task-local CLI test spellings are `changebudget authority grant create`, `changebudget authority grant revoke`, and reserved `changebudget authority rebind`. They are implementation test inputs, not a frozen public API; any later spelling change must update classifier, CLI, and tests as one reviewed batch. Rebind is blocked, not implemented, until separately designed.
- No TTY, interactive prompt, environment value, process ancestry, host permission, executable identity, `--actor`, agent declaration, or metadata proves human identity. Direct execution outside the supported governed Runtime Guard path is an explicit administrative trust premise, not proof of human presence.
- Direct create/revoke uses the same registry transaction and audit as the exact grant mutation; do not add an intermediate administration record, authentication artifact, generic auth/session/credential/security framework, or replacement mechanism.
- The supported governed-path denial matrix covers verified ChangeBudget shim, canonical Node invocation, `npm exec -- changebudget ...`, and `npx changebudget ...`. Existing first-party identity is used only for operation classification and currently has no SPEC-015 grant-admin command contract; classifier extension is required. Ambiguous routes within this supported boundary fail closed. Unsupported routes and malicious same-user OS bypass are outside the protection claim.
- Keep the V2 permission hook read-only. Valid grant reference remains non-consuming/non-upgrading preflight; no persistence-bearing `authorizeUse` from the hook. No managed START/AMEND/CLOSE ALLOW, force-close/reconcile-head, issue #29/#47, EvoSpec, Phase C+, stable release, or beta publication.
- No platform (including Windows/POSIX), OneDrive/cloud-sync, reparse/symlink behavior, or filesystem durability is supported without direct proof. Never fall back to path, remote, repository name, branch, copied UUID, executable identity, or host allow.
