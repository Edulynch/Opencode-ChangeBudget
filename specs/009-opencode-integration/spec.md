# Feature Specification: Native OpenCode V2 Project Integration (SPEC-009)

**Feature Branch**: `009-opencode-integration`
**Created**: 2026-08-18
**Status**: Implemented on `master`

## Problem Statement

ChangeBudget needs a repeatable, project-local way to load its OpenCode Runtime Guard without asking users to hand-write an integration file. OpenCode V2 automatically loads JavaScript plugins from `.opencode/plugins/`, and its native plugin API provides session-context and permission-evaluation hooks.

The integration has one responsibility: create a marked loader at `.opencode/plugins/changebudget.js` that re-exports the compiled ChangeBudget V2 plugin through a Windows-safe `file://` URL. It must not create or edit `opencode.json`, instruction files, `AGENTS.md`, global configuration, or ChangeBudget state.

## Scope

ChangeBudget owns exactly one project resource:

| Resource | Path | Authority |
|---|---|---|
| Native V2 plugin wrapper | `.opencode/plugins/changebudget.js` | Generated by ChangeBudget; user-owned content is never overwritten |

The compiled plugin uses `@opencode/plugin@2.0.12` and the native `{ id, setup(ctx) }` shape. Its setup registers `ctx.session.hook("context", ...)` and `ctx.permission.hook("evaluate", ...)`.

The command never manages `opencode.json`, `.opencode/instructions/**`, `AGENTS.md`, or any other `.opencode/**` path.

## User Stories and Acceptance Scenarios

### Story 1 — One-command native V2 setup

As an OpenCode V2 user, I can run `changebudget integrate opencode` and load the Runtime Guard without editing project configuration.

1. In a disposable Git repository with no wrapper, install creates the wrapper with the ownership marker and current compiled-plugin URL.
2. Existing `opencode.json`, instruction files, and `AGENTS.md` remain byte-identical.
3. If the compiled plugin is absent, the command reports that `npm run compile` is required and writes nothing.

### Story 2 — Idempotent installation and stale-path repair

1. Repeating installation with the current wrapper reports `UNCHANGED` and changes no bytes.
2. A marked wrapper with an old URL reports `UPDATE` and only the wrapper is rewritten.
3. A user-owned wrapper reports `CONFLICT`, writes nothing, and remains unchanged.

### Story 3 — Preview and removal

1. `--dry-run` reports the wrapper action and performs no filesystem or Git mutation.
2. `--remove` deletes only a marked wrapper and removes empty `plugins/` and `.opencode/` directories only when safe.
3. Removal of a user-owned wrapper is refused without deletion.
4. Repeating removal reports `ABSENT` and succeeds.

### Story 4 — Native V2 runtime behavior

1. Importing the installed wrapper yields plugin id `changebudget` and a `setup` function; no alternate server contract or hook adapter exists.
2. `session.context` adds the ChangeBudget workflow context once per request.
3. `permission.evaluate` evaluates every resource and combines outcomes restrictively: `deny > ask > allow`.
4. Structured material decisions, when present in permission metadata, are normalized and passed to the existing evaluator; ordinary requests fabricate no material decision.
5. Hook failures fail closed for mutating operations and do not mutate ChangeBudget state.

## Functional Requirements

- **FR-001**: The CLI MUST provide `changebudget integrate opencode [--dry-run|--remove]`.
- **FR-002**: The command MUST manage only `.opencode/plugins/changebudget.js`.
- **FR-003**: The wrapper MUST contain a deterministic ownership marker and re-export the compiled default plugin through a `file://` URL.
- **FR-004**: The URL MUST be generated with `pathToFileURL()` and work with Windows drive letters, spaces, Unicode, and POSIX paths.
- **FR-005**: Installation MUST verify the compiled plugin exists before writing and give an actionable build message when it does not.
- **FR-006**: Only a marked wrapper may be updated or removed. A missing marker is a conflict.
- **FR-007**: Preflight MUST complete conflict detection before any write. A conflict produces zero writes.
- **FR-008**: Installation MUST be deterministic and idempotent; current content is `UNCHANGED`, marked stale content is `UPDATE`.
- **FR-009**: Dry-run MUST perform detection only and write nothing.
- **FR-010**: Removal MUST preserve all unrelated project files and clean only empty directories made unnecessary by wrapper removal.
- **FR-011**: The command MUST not create or edit `opencode.json`, instruction files, `AGENTS.md`, global OpenCode configuration, or `.changebudget/**`.
- **FR-012**: Installation/update MUST report an informational Git baseline warning for an untracked or modified wrapper and MUST never stage, commit, push, or amend.
- **FR-013**: The runtime package MUST use `@opencode/plugin@2.0.12` and the native V2 `Plugin.define({ id, setup })` contract.
- **FR-014**: Runtime setup MUST register only `session.context` and `permission.evaluate` for this integration.
- **FR-015**: Session context injection MUST be deterministic, local, and free of filesystem writes.
- **FR-016**: Permission evaluation MUST map internal `block` to V2 permission effect `deny` and aggregate multiple resources restrictively.
- **FR-017**: Permission evaluation MUST preserve an existing more restrictive effect and MUST never weaken `deny` to `ask` or `allow`.
- **FR-018**: Malformed lifecycle state or evaluator failure MUST produce a safe denial for a potentially mutating operation.
- **FR-019**: Structured material decisions MUST remain explicit and must enter the evaluator only through V2 permission metadata normalization.
- **FR-020**: Existing ChangeBudget lifecycle behavior, baseline legacy data modes, and execution-gate structured decisions MUST remain unchanged outside the plugin boundary.
- **FR-021**: The CLI and runtime MUST have no alternate API adapters, compatibility fallbacks, version detection, duplicate configuration, migration path, or pseudo-handoff transport.

## Runtime Contract

The compiled plugin receives `ctx.location.directory`, resolves the Git repository root, and registers:

```ts
Plugin.define({
  id: 'changebudget',
  async setup(ctx) {
    await ctx.session.hook('context', event => { /* append deterministic system text */ });
    await ctx.permission.hook('evaluate', event => { /* set effect/message */ });
  },
});
```

The evaluator continues to use ChangeBudget state, `runCheck`, active-contract resolution, and the existing material-decision governance model. The projection emits `allow`, `ask`, or internal `block`; the V2 permission event receives `allow`, `ask`, or `deny`.

## Data and Safety Model

```ts
type OwnershipState = 'MISSING' | 'MANAGED_CURRENT' | 'MANAGED_STALE' | 'CONFLICT';
type ResourceAction = 'CREATE' | 'UPDATE' | 'UNCHANGED' | 'REMOVE' | 'CONFLICT' | 'ABSENT';

interface IntegrationResult {
  operation: 'install' | 'remove' | 'dry-run';
  resources: { pluginWrapper: { path: string; action: ResourceAction; detail?: string } };
  runtimeGuardTargetExists: boolean;
  baselineWarning: string | null;
  readiness: 'READY' | 'NEEDS_ATTENTION';
}
```

The wrapper marker is the exact first line:

```text
// ChangeBudget-managed: do not edit. Re-run: changebudget integrate opencode
```

No manifest, version discriminator, or compatibility state is persisted. Staleness is determined by exact expected content.

## Success Criteria

- **SC-001**: A fresh disposable repository installs one correct wrapper and no other integration resource.
- **SC-002**: A second install is byte-identical and reports `UNCHANGED`.
- **SC-003**: Stale marked wrappers are repaired; user-owned wrappers are never overwritten.
- **SC-004**: Dry-run and all conflict paths perform zero writes.
- **SC-005**: Removal deletes only the marked wrapper and is idempotent.
- **SC-006**: `AGENTS.md`, `opencode.json`, instruction files, and unrelated plugins remain byte-identical.
- **SC-007**: Native wrapper import registers exactly `context` and `evaluate` hooks.
- **SC-008**: Twenty synthetic permission requests preserve restrictive `deny > ask > allow` aggregation and safe failure.
- **SC-009**: Windows and POSIX URL round-trips resolve to the compiled plugin entry.
- **SC-010**: Core CLI tests, baseline legacy modes, and structured execution-gate decisions remain green.

## Testing Requirements

All integration tests use disposable Git repositories. The suite covers clean install, idempotence, stale repair, conflict protection, dry-run, removal, Git baseline warnings, missing build output, wrapper import, session context, permission aggregation, malformed state, and structured material-decision metadata. No test inspects or modifies a personal/work repository or global OpenCode configuration.

## Non-Goals

- Editing `opencode.json` or any instruction file.
- Modifying `AGENTS.md` or global OpenCode configuration.
- Supporting an alternate OpenCode plugin API or translating between plugin generations.
- Automatic migration, version detection, duplicate configuration, or manifest state.
- Plugin copying/vendoring, network downloads, npm publishing, automatic Git operations, or OS-level sandboxing.
