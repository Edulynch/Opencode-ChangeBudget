# Tasks: Working Tree Baseline

**Authorities**: `spec.md`, `plan.md`, `research.md`, `data-model.md`, and `quickstart.md`. `spec.md` is normative for the 56 scenarios, public output, integrity handling, HEAD binding, read-only behavior, and B-to-C semantics.

**MVP strategy**: deliver the baseline contract and read-only capture first, then B-to-C projection through the existing evaluator, then reporting and lifecycle retention, then the complete deterministic matrix. A clean repository may use a lightweight baseline. No task may replace evidence with timestamps, ignore a whole path, reconstruct legacy evidence, or mutate user or Git state.

**Safety boundary**: writes are limited to ChangeBudget evidence under `.changebudget/**`. Start, check, status, and close must not write user files, `.git/**`, index content, refs, commits, stash, or nested worktrees. Unsupported nested dirty submodule work is disclosed as `HUMAN_REVIEW`, never `PASS`.

## Scope and non-goals

- Do not mutate user files, `.git/**`, index content, refs, commits, stash, nested worktrees, or scope policy.
